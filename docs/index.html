On-call Runbook Copilot

When an alert fires, it retrieves the matching runbook, checks the runbook's claims against the service's own logs, and writes an incident note with the root cause, the log lines that prove it, and the next steps. If nothing is confirmed it says UNKNOWN instead of guessing. Source on GitHub.

How it works

fault injector ──► HOI platform API (real code) ──► log store (SQLite) ──► alert rules │ hybrid retrieval over 16 runbooks (BM25 + LSA, Reciprocal Rank Fusion) ◄──┘ │ top 5 candidates verify: run each runbook's checks with read-only tools against the logs │ first runbook whose checks all pass, else UNKNOWN grounding gate (runbook exists, every cited log line exists) ──► incident note
